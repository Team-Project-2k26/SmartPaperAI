## Project Overview

SmartPaperAI is an academic AI/ML project that implements a complete **research paper understanding pipeline** using locally runnable open-source models. The system transforms a raw PDF into a richly structured analysis without relying on any paid external AI API.

---

## Problem Statement

The volume of academic publications doubles every few years. Researchers, students, and academics waste significant time reading papers that may not be directly relevant to their work. SmartPaperAI solves this by:

- Automatically extracting structured information from research papers
- Generating plain-language explanations of complex contributions
- Identifying research gaps and suggesting future directions
- Enabling natural-language Q&A grounded in the actual paper

---

## Features

| Feature | Description |
|---|---|
| **Structured Summary** | Abstractive summary generated by DistilBART |
| **Research Objective** | Auto-extracted from abstract/introduction |
| **Methodology** | Identified from methods/approach sections |
| **Key Findings** | Extracted from results/experiments sections |
| **Main Points** | Top-ranked sentences using TF-IDF + embeddings |
| **Key Insight** | Most important contribution with simple explanation |
| **Keywords** | Extracted using YAKE (unsupervised) |
| **Limitations** | Identified from discussion/conclusion |
| **Future Research** | ≥3 grounded research directions per paper |
| **Q&A Chatbot** | Retrieval-augmented QA using roberta-base-squad2 |
| **Source References** | Every answer includes which section/page it came from |

## Architecture

```
PDF Upload
      ↓
PDF Text Extraction (PyMuPDF)
      ↓
Text Cleaning & Normalization
      ↓
Section Detection / Segmentation (regex heuristics)
      ↓
Metadata Extraction (title, authors, DOI, year)
      ↓
Text Chunking (sentence-level, overlapping)
      ↓
Embedding Computation (all-MiniLM-L6-v2)
      ↓
┌─────────────────────────────────────────────┐
│           Analysis Pipeline                  │
│  • Extractive sentence ranking (TF-IDF +     │
│    cosine similarity + position weight)      │
│  • Abstractive summary (DistilBART)          │
│  • Key insight & simple explanation          │
│  • Future research direction generation      │
│  • Keyword extraction (YAKE)                 │
└─────────────────────────────────────────────┘
      ↓
Q&A Chatbot (semantic retrieval → roberta-base-squad2)
      ↓
React Frontend (structured results + chat)
```

## AI Models Used

| Model | Size | Purpose |
|---|---|---|
| `all-MiniLM-L6-v2` | ~80 MB | Sentence embeddings for semantic retrieval |
| `sshleifer/distilbart-cnn-12-6` | ~1.2 GB | Abstractive summarization |
| `deepset/roberta-base-squad2` | ~500 MB | Extractive question answering |
| `en_core_web_sm` (spaCy) | ~12 MB | NLP preprocessing |

> **Total first-run download: ~1.8 GB** — cached by HuggingFace after first download.  
> All models run **locally** — no API keys or internet connection needed after initial download.

## Installation

### Prerequisites
- Python 3.10+
- Node.js 18+
- Git

### 1. Clone the repository
```bash
git clone <your-repo-url>
cd research-paper-analyzer
```

### 2. Backend setup
```bash
# Install Python dependencies
pip install -r backend/requirements.txt

# Download the spaCy English model
python -m spacy download en_core_web_sm

# Copy environment file
cp .env.example .env
```

### 3. Frontend setup
```bash
cd frontend
npm install
cd ..
```

## Running the Application

### Backend (Terminal 1)
```bash
# From the research-paper-analyzer directory
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

> **First startup** will download HuggingFace models (~1.8 GB total). This takes 5–15 minutes depending on connection speed. Subsequent starts are instant.

### Frontend (Terminal 2)
```bash
cd frontend
npm run dev
```

Open **http://localhost:5173** in your browser.

### Using Docker (optional)
```bash
# Build and start both services
docker-compose up --build
```

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Server health + model status |
| `POST` | `/upload` | Upload a PDF (multipart/form-data, field: `file`) |
| `POST` | `/analyze` | Run full analysis (`{"document_id": "..."}`) |
| `POST` | `/chat` | Ask a question (`{"document_id": "...", "question": "..."}`) |
| `GET` | `/docs` | Interactive API documentation (Swagger UI) |

### Example: Upload + Analyze
```bash
# 1. Upload
curl -X POST http://localhost:8000/upload \
  -F "file=@paper.pdf" \
  | python -m json.tool

# 2. Analyze (use document_id from step 1)
curl -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"document_id": "abc123..."}' \
  | python -m json.tool

# 3. Chat
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"document_id": "abc123...", "question": "What is the main objective?"}' \
  | python -m json.tool
```

## Example Workflow

1. Open **http://localhost:5173**
2. Drag and drop a research paper PDF onto the upload zone
3. Click **Analyze Paper**
4. Wait 30–120 seconds for AI processing (progress steps shown)
5. Review the structured analysis:
   - Summary, Objective, Methodology, Findings
   - Key Insight with plain-language explanation
   - Keywords and Limitations
   - Future Research Directions (≥3, with evidence)
6. Use the embedded **Chat** to ask questions about the paper

## Limitations

- **Scanned PDFs**: PyMuPDF cannot extract text from image-only PDFs. OCR is not included in this version.
- **Model download time**: First run requires ~1.8 GB download. A fast internet connection is recommended.
- **GPU not required but recommended**: All models run on CPU. Inference is slower without a GPU (expect 30–60s per paper).
- **Section detection**: Heuristic regex-based — may miss non-standard section headings.
- **Language**: Currently English-only.
- **In-memory cache**: Processed documents are cached per server session and lost on restart.
